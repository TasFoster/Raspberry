# ОТЧЁТ — диагностика Clover (Raspberry Pi + Pixhawk/PX4) по MAVLink

**Дата:** 2026-06-01
**Объект:** дрон Clover, хост `clover-5653`, Raspberry Pi @ `192.168.11.1` (Wi-Fi AP),
к Pi по USB подключён полётник Pixhawk с прошивкой **PX4 v1.17.0** (`/dev/ttyACM0`, 115200).
**Управляющая машина:** Windows 11, подключение по SSH (`pi@192.168.11.1`, paramiko).

---

## 1. Что было сделано до поломки

### 1.1. Анализ исходного плана (`CLAUDE.md`)
- План был написан под «обобщённую» Raspberry Pi: пользователь `raspberry`, стек `libcamera`.
- По факту устройство — дрон **Clover**: SSH-логин `pi`, ОС Raspbian Buster (старый стек MMAL,
  без `libcamera`), домашний каталог `/home/pi/`. План скорректирован под реальные параметры.

### 1.2. Подключение
- `ping 192.168.11.1` — хост в сети (TTL=64, Linux).
- Прямой `ssh` с паролем неинтерактивен из-под инструментов; на Windows нет `sshpass`/`plink`.
- Решение: драйвер на **paramiko** (`run_probe.py`) — заливает локальный python-скрипт на Pi
  (через base64) и запускает его. Все проверки выполнялись скриптами на самой Raspberry.

### 1.3. Проверка связи с полётником по MAVLink (`mav_probe.py`)
Результат: **HEARTBEAT получен** на `/dev/ttyACM0 @ 115200`.
- autopilot: `MAV_AUTOPILOT_PX4`
- type: `MAV_TYPE_QUADROTOR`
- flight_sw_version: **1.17.0**
- sys=1, comp=0; на старте `MAV_STATE_UNINIT`, disarmed.

### 1.4. Расширенная телеметрия (`mav_telemetry.py`)
- Режим `LOITER`, **DISARMED**.
- Батарея: **15.04 В (4S)**, ток ~0.11 А (холостой), 100%.
- CPU load: **86.6%** (подозрительно высоко для покоя).
- IMU/Attitude: roll −2.6°, pitch +3.0°, yaw −68.9° — исправно.
- VFR_HUD: высота ~151 м (барометр), скорости 0, throttle 0%.
- **GPS: сообщений `GPS_RAW_INT` нет** — модуль не подключён.

### 1.5. Проверка готовности к арму (`mav_prearm.py`, read-only)
- Гироскоп / акселерометр / магнитометр / барометр — **все healthy** (калибровка зачлась).
- GPS — отсутствует. RC-приёмник — отсутствует. AHRS — не present.
- Состояние — `MAV_STATE_UNINIT` (НЕ `STANDBY`).

### 1.6. Попытка bench-арма (`mav_arm.py`) — ВИНТЫ СНЯТЫ (подтверждено пользователем)
Изменены параметры PX4, чтобы разрешить арм на столе:
- `COM_RC_IN_MODE = 4`  → арм без RC-приёмника **(ВНИМАНИЕ: RC сейчас ОТКЛЮЧЁН)**
- `COM_ARM_WO_GPS = 1`  → арм без GPS
- `CBRK_USB_CHK = 197848` → разрешить арм при подключённом USB

Переключение в `STABILIZED` — `MAV_RESULT_ACCEPTED`.
Команда `ARM` → **`MAV_RESULT_TEMPORARILY_REJECTED`**, флаг ARMED = False. Моторы не запускались.

### 1.7. Поиск причины отказа
- `mav_arm_reason.py`: повторный ARM → снова `TEMPORARILY_REJECTED`, без `STATUSTEXT`.
- `mav_reboot_arm.py`: перезагрузка полётника (`MAV_CMD_PREFLIGHT_REBOOT_SHUTDOWN`),
  переподключение — **состояние снова `UNINIT`**, ARM снова отклонён. Перезагрузка не помогла.
- `mav_shell_check.py` / `mav_shell_check2.py`: вход в **системную консоль PX4 (nsh)** через
  `SERIAL_CONTROL` поверх MAVLink. Получено:
  - `commander check` → **`Preflight check: FAILED`**
  - `ekf2 status` → `attitude: 1, local position: 0, global position: 0` (есть ориентация,
    **нет позиции** — GPS `selected GPS: 0`)
  - `sensors status` → гиро/акс/маг/баро OK; замечены `IMU message missed` и пропуски данных
    на втором IMU (на фоне высокого CPU).

### 1.8. Потеря связи
- Очередной запуск упал с `Error reading SSH protocol banner`.
- Диагностика: Wi-Fi `State: disconnected`; пинг `192.168.11.1` стал отвечать с `TTL=128`/<1 мс
  (это локальный стек, не Pi); сеть `clover-5653` перестала вещать; `netsh wlan connect` →
  «network not available». Вывод: **точка доступа дрона отключилась** (питание/зависание Pi).

## 2. Главный итог диагностики (на момент обрыва связи)

- **Командный канал MAVLink полностью исправен** — параметры пишутся, режимы переключаются,
  ACK'и идут, доступна системная консоль PX4. Ограничения со стороны управляющей машины нет.
- **Арм блокирует сам автопилот:** `Preflight check: FAILED`, PX4 не выходит из `MAV_STATE_UNINIT`
  в `STANDBY`. Датчики откалиброваны и healthy, но у EKF2 **нет оценки позиции** (нет GPS),
  и preflight не проходит. Построчные причины отказа дочитать не успели — оборвалась связь.

## 3. АВАРИЯ (заявлено пользователем)

⚠️ **Загорелся силовой кабель** от платы распределения питания к контроллеру.
Пользователь отключил питание, затем подключил кабель обратно.

**Оценка:** возгорание = короткое замыкание / перегрузка. Повторное подключение **не устраняет
причину**. Подача питания на повреждённую цепь и запуск моторов опасны: риск повторного
возгорания, пожара LiPo-аккумулятора, выхода из строя ESC/PDB/полётника.

**Запуск двигателей ПРИОСТАНОВЛЕН до устранения неисправности.**

## 4. Что делать дальше

### 4.1. Сначала — железо (обязательно, до любых команд на моторы)
1. **Отключить батарею**, если подключена.
2. Осмотреть обгоревший кабель и оба разъёма: оплавление, гарь, оголённая медь.
3. **Заменить повреждённый кабель целиком** (не ремонтировать подмоткой).
4. Найти причину КЗ/перегруза: закушенный провод, замыкание на раму, полярность,
   достаточность сечения под токи моторов.
5. Прозвонить мультиметром отсутствие КЗ между «+» и «−» силовой цепи.
6. Только после этого — осторожная подача питания **без винтов**, контроль нагрева.

### 4.2. Потом — продолжение диагностики арма (когда железо исправно и Wi-Fi вернётся)
1. Переподключиться: `netsh wlan connect name=clover-5653`, дождаться сети.
2. Дочитать построчный `commander check` (точные причины preflight fail).
3. Разобраться с высоким CPU 86% и пропусками IMU.
4. При необходимости — арм в `STABILIZED`/`MANUAL` без позиции (винты сняты).

### 4.3. Откат изменений (перед реальными полётами)
- **Вернуть `COM_RC_IN_MODE = 1`** (сейчас 4 — радиоуправление отключено!).
- Пересмотреть `COM_ARM_WO_GPS` и `CBRK_USB_CHK` под штатный режим эксплуатации.

## 5. Файлы проекта (на управляющей машине, `D:\Projects\Raspberry\`)
- `run_probe.py` — драйвер: SSH (paramiko) → заливка скрипта на Pi → запуск.
- `mav_probe.py` — поиск полётника и HEARTBEAT.
- `mav_telemetry.py` — расширенная телеметрия (батарея/GPS/attitude/режим).
- `mav_prearm.py` — read-only проверка готовности и здоровья датчиков.
- `mav_arm.py` — настройка параметров + bench-арм/disarm.
- `mav_arm_reason.py` — захват причины отказа арма.
- `mav_reboot_arm.py` — перезагрузка полётника + повторный арм.
- `mav_shell_check.py`, `mav_shell_check2.py` — консоль PX4 (nsh) по MAVLink.
