# Raspberry Pi Camera Check — План работы

## Цель
Подключиться по SSH к Raspberry Pi 3 по адресу `192.168.11.1`, проверить
состояние подключённой камеры и, если она доступна, сохранить лог статуса
работы камеры в домашнюю директорию пользователя `raspberry`.

## Исходные данные
- **Хост:** `192.168.11.1` (Raspberry Pi 3, подключение по Wi-Fi)
- **Пользователь SSH:** `raspberry` (предположительно; уточнить при необходимости)
- **Рабочий каталог на хосте:** `/home/raspberry/`
- **Платформа управляющей машины:** Windows 11, OpenSSH доступен
  (`C:\Windows\System32\OpenSSH\ssh.exe`)

## План действий

### 1. Проверка доступности хоста
- `ping 192.168.11.1` — убедиться, что устройство в сети.

### 2. SSH-подключение
- Команда: `ssh raspberry@192.168.11.1`
- При первом подключении потребуется подтвердить отпечаток ключа и ввести
  пароль (или использовать ключ, если он уже настроен).
- Если имя пользователя другое (например, `pi`), повторить с корректным логином.

### 3. Детектирование камеры на устройстве
Выполнить последовательно несколько проверок, чтобы покрыть как старый,
так и новый стек (Raspberry Pi OS Bullseye/Bookworm):

1. **Новый стек (libcamera):**
   - `libcamera-hello --list-cameras`
2. **Старый стек (raspistill / vcgencmd):**
   - `vcgencmd get_camera` — вернёт `supported=1 detected=1`, если камера видна.
   - `raspistill -t 1 -o /dev/null` — тестовый снимок (если установлен).
3. **USB / V4L2 камеры:**
   - `ls /dev/video*`
   - `v4l2-ctl --list-devices` (если утилита установлена).
4. **Информация о модулях ядра:**
   - `dmesg | grep -iE 'camera|bcm2835|imx|ov5647'`

### 4. Формирование лога
- Имя файла: `/home/raspberry/camera_status_<YYYYMMDD-HHMMSS>.log`
- Содержимое:
  - Дата/время запуска проверки
  - Имя хоста (`hostname`) и версия ОС (`cat /etc/os-release`)
  - Результаты всех команд из шага 3
  - Итоговый статус: `CAMERA_OK` или `CAMERA_NOT_DETECTED`
- Лог создаётся **только** если хотя бы одна из проверок подтверждает наличие
  камеры (по требованию задачи: «если есть подключение — создай лог»).

### 5. Возврат результата
- Вывести путь к созданному логу и итоговый статус в консоль.
- При отсутствии камеры — сообщить об этом и **не создавать** файл.

## Открытые вопросы / уточнения
1. **Имя пользователя SSH** — `raspberry`, `pi` или другое?
2. **Метод аутентификации** — пароль или SSH-ключ? Если пароль, потребуется
   интерактивный ввод (нужно будет запустить через `! ssh ...` в чате).
3. **Тип камеры** — CSI-модуль (ribbon) или USB-камера? Это влияет на набор
   проверок, которые имеют смысл.
4. **Поведение при отсутствии камеры** — оставляем «лог не создаётся» или
   всё-таки записываем диагностический лог со статусом `CAMERA_NOT_DETECTED`?
